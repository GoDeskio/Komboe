Accounts and sign-in

What is a Komboe account?

One Komboe account syncs the web vault, browser extensions, phone, desktop, command line and the assistant. You sign in with your email and master password, and you can add a passkey and two-step login.

Does Komboe ever see my master password?

No. The home page and the web vault hash the master password on the device. Only that hash is sent, and the vault is encrypted before it syncs.

Can an admin reset my master password?

No. There is no backdoor and no admin password reset. Keep your recovery kit safe.

Does this website ask for my password?

Yes. The home page sign-in form uses the same flow as the web vault, including a two-step code when the account has one. The password stays in the browser and is not stored on this site.

What about self-hosting?

Self-hosted servers use local Komboe accounts by default. Organizations can optionally add enterprise single sign-on. Vault decryption still needs each person's master password. A self-hosted Komboe server does not contact Komboe. Outside services stay off unless you turn them on. Desktop and CLI update checks stay off until you point them at a feed you host. A breach check runs only when you ask for it. Password checks send only a k-anonymity hash prefix, never the password. The data breach report sends your email address to your Komboe server, which forwards it only if the operator has configured a breach-check key. The web vault uses the server it was loaded from. Until you save a server URL, some apps still have a cloud default compiled in. Set your server URL when you first sign in.

Komboe assistant

Asks your Komboe agent after you sign in. It can explain a feature, suggest next steps, or generate a password. It never reads vault items.
